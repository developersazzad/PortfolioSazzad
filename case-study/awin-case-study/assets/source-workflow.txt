## 1. HIGH-LEVEL WORKFLOW ARCHITECTURE
*(Conceptualized based on core system logic and API bridging)*

The AWIN ecosystem operates on a highly decentralized, microservice-inspired architecture. The workflow is divided into three primary operational loops:
1. **Acquisition & Onboarding (Website):** Users land on the dynamically CMS-driven public website. They review live packages and are funneled into the PWA.
2. **Engagement & Transactions (PWA):** Once authenticated via the API-driven PWA, users deposit funds (handled asynchronously). They browse Regular or EXP (Special) packages, select numbers (e.g., 6/7 limit logic), and execute ticket purchases. The API strictly validates wallet balances and records transactions without allowing direct DB access.
3. **Control & Resolution (Admin Panel):** Administrators monitor the financial queue (approving Top-ups and Withdrawals via `balance_data`). The algorithmic engine runs either manually or via Cron to evaluate winning sequences. Post-draw, the Admin publishes the results, instantly pushing updates via API to the PWA and dispatching omnichannel notifications (WhatsApp/Email/SMS).
